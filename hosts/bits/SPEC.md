# Bits

Work laptop for Birger Rydback at Bits. This is an AMD-based laptop running NixOS with the Hyprland Wayland compositor (scrolling layout mimicking niri), configured for software development and daily office use.

## Key Features

- Hyprland compositor using the built-in scrolling layout configured to mimic niri's scrollable tiling (see `modules/window-manager/SPEC.md` for the niri-equivalent keybinds), with Vicinae launcher (wifi and bluetooth extensions; monitors through monitormenu)
- Development tooling: toolchains (Go, Node, Python, Kotlin) and cloud tools (LocalStack, AWS CLI/CDK, Terraform) come from each repository's own dev shell (`flake.nix` + `.envrc` with `use flake`, cached by nix-direnv; `~/Development/cloud` has one), not from the system: `my.development` keeps only gh, Claude Code and opencode (`infra.enable = false`, no language flags). The editor keeps its Go and TypeScript language servers (`my.editor.languages`); Kotlin is gone from the editor. Plus direnv, git and the SSH agent
- Firefox browser (home-manager managed, `my.firefox.enable`) with Slack; Discord comes with the games module
- Alacritty terminal with Bash shell and Starship prompt
- Disk encryption enabled for security
- Fingerprint reader (Goodix `27c6:658c`, libfprint's built-in driver: `driver = "generic"`): fingerprint or password at the same prompt for login, sudo and polkit; hyprlock reads it natively
- `my.profiles.laptop` (implies workstation): touchpad, backlight, TLP power management, battery notifications, audio, bluetooth, printing, firmware updates
- Battery monitoring and power management (TLP, see `modules/power-management/SPEC.md`). The diagnostic posture that chased the hard power-offs — AC capped to `low-power` / `low` amdgpu DPM plus `forensics.enable` — has been **retired**, because the telemetry it collected identified the cause: the pack reports empty at 0.5 Wh and then runs for another 100 minutes, i.e. a degraded cell stack *and* a fuel gauge that has lost calibration, so reported percentages and time-remaining figures are meaningless. **The pack is the outstanding hardware item**; BIOS and EC were updated to 0.1.81 / 0.1.67 on 2026-09-25.
- Tuned for a light login: nothing autostarts, Docker (rootless and rootful), CUPS, sshd and fwupd start on demand, and Hyprland drops blur/shadows on battery. Measured idle draw is ~3.4 W with the screen off against ~10 W with the panel at full brightness, so the display dominates everything else on this machine.
- Docker for containerized development — rootless only at boot; the rootful daemon is socket-activated (see `modules/docker/SPEC.md`)
- Offline media for travel: `media` (mpv + yt-dlp) for DRM-free sources. **Waydroid is currently disabled** (see below); when it was on it provided Netflix's Android app for offline downloads — SD only, with Disney+/HBO Max hard-blocked (see `modules/waydroid/SPEC.md`)
- Bluetooth and printer support; the laptop profile drops `cups-browsed` so `cupsd` stays socket-activated instead of running from boot
- Moonlight client (`my.game-streaming.client`, 1920x1200@60 to match the panel, otherwise module defaults: 100 Mbps, HDR, auto codec/decoder) for streaming the desktop's Sunshine session over the tailnet. Pairing is a one-time manual step: wake the desktop with `ssh controller wake-desktop`, add `desktop.ts.rydback.net` in Moonlight, then approve the PIN at `https://desktop.ts.rydback.net:47990`
- Steam (`my.games`, Steam-focused: Proton-GE from unstable in the compatibility list, MangoHud only for games launched with `mangohud`, no store launchers, Wine prefix managers, emulators or BoilR; Battle.net through `wineApps.battlenet`, the `battlenet` command, prefix `~/Games/battlenet`). Steam and everything it launches render on the discrete Navi 24 (`my.games.steam.env.DRI_PRIME = "pci-0000_03_00_0"`) while Hyprland composites on the Rembrandt iGPU; the Steam client keeps the dGPU awake while open, so close it on battery. Per game, `gamemoderun %command%` (or `gamemoderun mangohud %command%`) adds renice and switches the ACPI platform profile to `performance` for the duration (`my.power-management.platformProfiles.gaming`); AC otherwise stays on `balanced`. Nothing else from the gaming-station profile was copied (no `mitigations=off`, zen kernel, performance governor or low-latency audio): the SteamOS sysctls come with the games module. `~/Games` holds a stale Steam library folder from an earlier install (re-add it under Steam → Storage, or delete it)
- Taildrop (`my.taildrop`, on by default for the admin user): Mod+Shift+S sends the clipboard to any tailnet device, phones included; received files land in `~/Downloads/taildrop` and received clipboards go straight to the clipboard. The admin user is the host's tailscale operator
- Project tracker CLI (`my.deck`, Nextcloud user `birger`): `deck` reads and updates the Nextcloud Deck boards on controller; the app password comes from the vault (`common.yaml` → `/run/secrets/deck-token-birgerrydback`). Claude Code uses it through `.claude/skills/deck`. See `modules/deck/SPEC.md`
- 3D printing toolchain: PrusaSlicer, OpenSCAD (dev snapshot), FreeCAD (`my.printing-3d` with `cad.enable`, see `modules/printing-3d/SPEC.md`)
- SMB network share browsing in Thunar (GVFS + Avahi/mDNS discovery)
- No emulation client or Syncthing on this work laptop (dropped for lightness)
- Colemak keyboard layout
- Theming with the kanagawa scheme (`my.theming.scheme`: stylix apps, the editor's kanagawa.nvim, waybar/Hyprland colors) and Banana cursor
- Editor: nvim (`modules/editor`) with Nix, Go, Kotlin and TypeScript support
- sops-nix integration: SSH keys delivered from the external `nix-vault` flake input; OpenSSH and pcscd auto-enabled by `my.sops`
- SSH client config generated from the registry (`modules/ssh`): `ssh controller` / `ssh desktop` connect as `betongsuggan` with the `bits` key, without YubiKey touch; the GitHub hosts are declared in the user file
- `betongsuggan@controller`'s SSH key is authorized on `birgerrydback` so the controller host can SSH back into bits (`sshFrom` on this account in `lib/default.nix`); the same registry entries generate the `Host controller` / `Host desktop` client blocks
- Firewall with ports open for the dev server (8080) and 3010. No LocalSend (dropped 2026-10-31; Taildrop covers file sharing)
- `/etc/hosts` maps `bits.execute-api.localhost.localstack.cloud` to localhost for LocalStack API Gateway development

## Notes

- Hardware: AMD CPU with `amd_pstate=active` frequency scaling and microcode updates
- Kernel: Linux 6.18; on battery TLP applies amdgpu Adaptive Backlight Management (level 3)
- `pcie_aspm=force`: BIOS 0.1.81 still marks ASPM unsupported in the FADT, which would leave TLP's `PCIE_ASPM_ON_BAT = powersupersave` a no-op. Measured 2026-09-25 at 40 % brightness: 5.39 W idle on `powersupersave` vs 5.87 W on `default` (the BIOS enables L1.2 itself; forcing adds NVMe clock PM and dGPU L0s). If NVMe, Wi-Fi or the SD reader misbehave (AER errors, dropouts, failed resume), remove it
- **Discrete GPU at boot (early KMS).** `amdgpu` is loaded from the initrd for the Navi 24 (03:00.0, render-only: the panel and every output hang off the iGPU at 67:00.0). Loaded from stage 2 it probed 20-35 s in (udev coldplug after the LUKS prompt) and failed in three of six boots between 2026-10-10 and 2026-10-26 with `failed to read discovery info from memory, vram size read: ffffffff`, leaving no dGPU at all. In every good boot amdgpu had enabled the device before `tlp.service` started; in two of the three bad boots TLP started first: its `RUNTIME_PM_ON_*=auto` also covers the still driverless dGPU and its root port 00:01.1, and the PCI core lets a driverless endpoint drop to D3cold with its bridge, so the probe reads all-ones. In the initrd amdgpu probes at ~2 s, before any runtime-PM policy; its own BOCO runtime PM powers the dGPU down afterwards (`amdgpu 0000:03:00.0: amdgpu: Using BOCO for runtime pm`). One failure (2026-10-12) predates TLP's start, so `pcie_aspm=force` remains a suspect: if `journalctl -k -b | grep -E '0000:03:00.0.*(VRAM|probe with driver amdgpu failed)'` ever shows the failure again, drop that flag first. Side effects: device numbering is now fixed (dGPU card0/renderD128, iGPU card1/renderD129; the Waydroid notes use by-path) and the initrd carries amdgpu's firmware (measure `du -sh /boot/EFI/nixos` after the first build; 10 generations must fit the 1 GB ESP). Recovery without a reboot when the probe failed: `echo on > /sys/bus/pci/devices/0000:00:01.1/power/control; echo 0000:03:00.0 > /sys/bus/pci/drivers/amdgpu/bind`
- **Waydroid is disabled as of 2026-09-17.** It crashed Hyprland twice in three hours: Waydroid's gralloc allocates Android surfaces on the discrete Navi 24 (`gralloc.gbm.device=/dev/dri/renderD128` in `/var/lib/waydroid/waydroid_base.prop`) while Hyprland composites on the Rembrandt iGPU (`renderD129`), so every surface crosses GPUs as a DCC-compressed dmabuf. That reset the iGPU, and Hyprland aborts on `GL_UNKNOWN_CONTEXT_RESET` because it has no reset-recovery path. Re-enabling requires first repointing gralloc at the iGPU render node — `gralloc.gbm.device=/dev/dri/by-path/pci-0000:67:00.0-render` (by-path, because `renderD*` numbering is not stable across boots)
- Waydroid pulls in `psi=1` on the kernel command line, so toggling it either way needs a reboot, not just a `nixos-rebuild switch`; it also forces `pkgs.waydroid-nftables` because 6.18 no longer ships `ip_tables`
- Boot: systemd-boot (secure boot not enabled)
- Firmware updates via fwupd (deferred to on-demand start)
- When Waydroid is enabled, its `waydroid-container` unit is deliberately not wanted by `multi-user.target`; use `waydroid-up`
- Timezone: Europe/Stockholm
- **Closure** 2026-10-31: 25.63 GiB after dropping VLC, gedit, gparted, GIMP, Okular (→ zathura), htop/btop, d2, android-tools and LocalSend (was 27.46 GiB with the games module). Older measurement: (measured 2026-10-22 on the running generation, `nix path-info -S /run/current-system`, before the games module landed on 2026-10-30; re-measure after that switch): 25.2 GB (23.5 GiB), 2871 store paths, nvim included (its closure is 3.4 GiB since the editor flake stopped bundling toolchains). The previous laptop-performance pass recorded 24.5 GB *without* nvim. Largest single paths: kotlin-lsp 1.2 GiB (editor, Kotlin), clang/llvm libs and vtk/gfortran/ifcopenshell ≈ 2.5 GiB together (all FreeCAD, `my.printing-3d.cad`), linux-firmware 0.8 GiB, ungoogled-chromium 0.76 GiB, discord 0.6 GiB, two JDKs (`jdk` for kotlin and `jdk-headless` pulled by ktfmt) 1.1 GiB, playwright's three browsers 0.9 GiB pulled in by `d2`. Measure the same way after changes; `nix path-info -rs /run/current-system | sort -k2 -n | tail` lists the big ones (sort by bytes; `sort -h` does not parse KiB/MiB).
- The vicinae file indexer is off declaratively (`programs.launcher.vicinae.fileIndex.enable`, default false → `autoIndexing: false` in the store-linked settings.json); nothing to toggle in the UI.
